# W6 theme-node verdict: the seam closes, erasure re-proves, and the estate collapses into one theme — 2026-11-28

Ticket #46 is implemented and measured through the seam
(`2026-11-28-w6-execution-plan.md` is the binding plan; the branch is
`w6-theme-nodes`). The estate perception call now carries theme nodes when
asked, the theme policy version sits in the engine hash, and `eraseEntity`
re-derives theme nodes with the diff receipt recording it. The honest headline
is not a quality claim: on the synthetic estate the agglomeration produces
exactly one theme node, and the reading below says why that is the correct
result for this corpus rather than a defect.

## 1. What the seam outputs now

`perceiveMulti(inputs, { themeLinking })` (opt-in; unset leaves the output
byte-for-byte what it was, and every prior seam test stays green). Set, it
scores a deterministic lexical shortlist with the W5 int4 artifact (the pair
graph's `linkProb` and `themeSim` outputs; the tokenizer, manifest pins, and
model hash travel inside the artifact metadata), agglomerates certified joins
with a canonically ordered union-find (order-independent by construction),
and adds to the output: `themeNodes` (members, anchor exemplars, evidence
spans, score distribution, policy version, model sha), `themeLinks` (every
scored candidate with its join or abstain decision), and `themeChannel`
(counts plus the disagreement report). Fail-closed typed errors throughout:
`WEFT_THEME_WEIGHTS_MISSING`, `WEFT_THEME_RUNTIME_MISSING`, and seven more
codes for malformed or mismatched artifacts; there is no fallback similarity
score anywhere in the path.

Theme nodes enter the Company-Brain connection graph as typed nodes
(`type: 'theme'`) with `THEME_MEMBER` edges from each member chunk's file
node (`scripts/run-company-brain-slice.mjs --theme`).

## 2. The estate run: one theme node, and why

Policy `weft-theme-agglomeration-v1` (join threshold 0.5, similarity floor
0.3, anchor k 3, shortlist 64; no tuning performed):

- 383 candidate pairs scored; 287 joins, 96 abstains
- 97 identity-disjoint joins (the cross-department outcome the spec wants)
- 69 disagreements recorded (identity-linked pairs the theme channel
  refused, scores attached for human review)
- Agglomeration output: 1 theme node, 30 members, anchors chunk_1,
  chunk_10, chunk_11
- In-node score spread: linkProb min 0.523, median 0.99999, max 1.0;
  themeSim min 0.665, median 0.859, max 0.969

Every scored-pair endpoint landed in one node, and all 96 abstained pairs
have both endpoints inside that same component. This is transitive closure
doing what it is defined to do on a corpus whose files are all about one
company's one quarter: the estate is topically homogeneous, and the W5 pair
graph separates lexical-overlap pairs almost perfectly, so the closure has
no cut to make. The verdict is not that theme linking works at 100 percent
coverage; it is that on this fixture one theme is the construction-valid
answer, and the disagreement report plus the score distribution are what
keep a human able to see that. Threshold recalibration needs a corpus with
more than one theme to mean anything, and that measurement belongs to the
heterogeneous-corpus work (not this ticket).

## 3. Erasure re-proofs with theme nodes present

Erasing an EMAIL-class entity from the theme-carrying corpus (one sample;
corpus sha `ff6eadca...` to `018a968a...`):

- `themeReDerived: true`
- theme nodes 1 before, 1 after; the member set shrank, so the node id
  changed (`theme:36ac2d1a...` to `theme:95c37b76...`) and the receipt
  lists both in `changedThemeNodeIds`
- 28 scored pairs invalidated by the erased content (383 to 355 surviving)
- `diffVerified: true`, every pre-existing byte-diff guarantee intact

The erasure drift guard now throws on policy-version mismatch, so a corpus
built under one theme policy cannot be erased under another.

## 5. Follow-ups this ticket leaves open

1. **Threshold recalibration needs a heterogeneous corpus.** One theme on a
   one-theme fixture is unfalsifiable as a quality claim; the count is
   construction validation only and no number from this estate goes in any
   paper.
2. **The results-clobber interaction is #48's lane.** The default-run slice
   test rewrites the committed results with no-theme bytes on every CI run,
   so after checkout plus suite the working tree disagrees with HEAD until
   regeneration; combined with Windows autocrlf churn this is exactly the
   artifact-regeneration hygiene #48 exists to fix.
3. **The metadata read is version-coupled.** onnxruntime-node 1.31.1
   exposes no model-metadata API, so the linker scans the ONNX protobuf's
   field 14 directly; a pinned dependency range belongs in the release
   packaging ticket (#47).
4. The 240-word length caveat and the unseen-style routing question stay
   open from W4/W5.
